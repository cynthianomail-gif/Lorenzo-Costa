## 3. 合成機制

### 基礎合成（1×2 合成符）

**觸發條件：**  
同色角色（colorId=C, type=角色）與同色武器（colorId=C, type=武器）  
於**同一行（row）水平相鄰**（col 相差 1）

**觸發結果：**
1. 兩格合併為 1×2 合成符，視覺上角色拿著武器，橫跨 col 與 col+1
2. 盤面上所有 colorId=C 的圖示右上角顯示 **×splitCount[C] 徽章**（初始 ×2）
3. 若同一局同色（colorId=C）已合成過，splitCount[C] 額外 +1（即 ×3、×4…）
4. 進入 Ways 計算與連爆流程

**資料結構：**
```js
// 每局開始時重置
let splitCount = [1, 1, 1, 1]; // 4色，index = colorId（0=紅,1=黃,2=藍,3=綠）
                                // 未合成=1，第一次合成後=2，同色再合成=3，以此類推
let synthesizedColors = new Set(); // 本局已合成的顏色（用於JP判定）
let mergedCells = []; // [{col, row, colorId, size: 2|4}]
                      // col = 合成符最左格，row = 合成發生的行
```

**splitCount 更新規則：**
- 觸發合成時：若 `!synthesizedColors.has(C)` → `splitCount[C] = 2`（首次）
- 若 `synthesizedColors.has(C)` → `splitCount[C] += 1`（同色再合成，額外+1）
- 將 C 加入 `synthesizedColors`

### 進階合成（1×4 合成符）

**觸發條件：**  
兩個**不同色**的 1×2 合成符於同一行相鄰  
（合成符A在col, 合成符B在col+2，即B緊接在A右方）

**觸發結果：**
1. 四格合併為 1×4 進階合成符，橫跨 col 至 col+3
2. 兩色的 splitCount 各自 +1

### JP 觸發條件
**同一局內 4 種顏色（紅/黃/藍/綠）全部完成合成**  
→ 觸發宙斯或赫拉 JP（翻牌二選一，沿用原版 drawBossCardPick 動畫）  
→ JP 值沿用原版累積彩金邏輯

## 4. 得分計算

### 公式
```
Win = 押注額 × 圖示賠率(matchCount) × Ways
```

### 連線判定（標準 Ways，左→右連續列）
```
對每一種符號（共8種），檢查從第0列開始能連幾列：

calcSymbolWin(symId, board, splitCount):
  colorId = Math.floor(symId / 2)
  split = splitCount[colorId]

  // 計算各列的有效數量（普通格 + 合成符替代）
  colCounts = []
  for col in [0..4]:
    count = 0
    for row in [0..3]:
      cell = board[col][row]
      if cell.id === symId: count++
      // 1×2 或 1×4 合成符同時替代該色角色與武器
      if cell.isMerged && cell.colorId === colorId: count++
    colCounts[col] = count * split  // 分裂倍數套入

  // 找出從左起連續有符號的列數（matchCount = 3/4/5）
  matchCount = 0
  ways = 1
  for col in [0..4]:
    if colCounts[col] === 0: break
    matchCount++
    ways *= colCounts[col]

  if matchCount < 3: return 0
  rate = PAYOUTS[symId][matchCount - 3]  // 賠率表查詢
  return bet * rate * ways
```

### 賠率表

| 符號 ID | 名稱 | 5連 | 4連 | 3連 |
|---------|------|-----|-----|-----|
| 0 | 紅色角色 | 0.80 | 0.60 | 0.40 |
| 2 | 黃色角色 | 0.60 | 0.30 | 0.20 |
| 4 | 藍色角色 | 0.60 | 0.30 | 0.20 |
| 6 | 綠色角色 | 0.60 | 0.30 | 0.20 |
| 1 | 紅色武器 | 0.50 | 0.30 | 0.20 |
| 3 | 黃色武器 | 0.40 | 0.30 | 0.20 |
| 5 | 藍色武器 | 0.40 | 0.30 | 0.20 |
| 7 | 綠色武器 | 0.40 | 0.30 | 0.20 |

```js
// PAYOUTS[symId] = [rate3, rate4, rate5]
const PAYOUTS = [
  [0.40, 0.60, 0.80], // 0 紅色角色
  [0.20, 0.30, 0.50], // 1 紅色武器
  [0.20, 0.30, 0.60], // 2 黃色角色
  [0.20, 0.30, 0.40], // 3 黃色武器
  [0.20, 0.30, 0.60], // 4 藍色角色
  [0.20, 0.30, 0.40], // 5 藍色武器
  [0.20, 0.30, 0.60], // 6 綠色角色
  [0.20, 0.30, 0.40], // 7 綠色武器
];
```

### 計算範例
- 紅色角色 3連，第1/2列各有1個，第3列有1個且 splitCount=2
  → colCounts = [1, 1, 1×2] = [1, 1, 2]
  → Ways = 1 × 1 × 2 = 2
  → Win = 100 × 0.40 × 2 = **80**

- 若第3列有2個物理符號且 splitCount=2
  → colCounts[2] = 2 × 2 = 4，Ways = 1 × 1 × 4 = 4
  → Win = 100 × 0.40 × 4 = **160**

## 5. 遊戲狀態機

```
IDLE
  → (Spin) → SPINNING
SPINNING
  → (落定) → SYNTHESIS_CHECK
SYNTHESIS_CHECK
  → 掃描全盤：找同色角色+武器相鄰（含1×2找1×2相鄰）
  → 有合成 → 播放合成動畫 → 更新splitCount / mergedCells
  → WAYS_WIN
WAYS_WIN
  → 計算 Ways 得分，播放飛分動畫
  → 檢查 JP 條件（synthesizedColors.size === 4）
  → 有得分符號 → POPPING
  → 無得分 → JP_CHECK
POPPING
  → 消除符號（含合成符展開格）
  → GRAVITY
GRAVITY
  → 上方補入新符號，下落動畫
  → SYNTHESIS_CHECK（再次掃描）
JP_CHECK
  → 若 JP 已觸發 → drawBossCardPick 動畫 → 結算
  → IDLE（重置 splitCount / synthesizedColors / mergedCells）
```

## 6. 視覺規格

### 分裂徽章
- 位置：格子右上角
- 樣式：圓角矩形，底色對應顏色，白字顯示 `×2`、`×3`…
- 對象：所有 colorId=C 的普通格（非合成符本身）

### 合成符渲染
- 1×2：橫跨 col 至 col+1，高度 = CELL_SIZE，寬度 = CELL_SIZE×2
- 1×4：橫跨 col 至 col+3，高度 = CELL_SIZE，寬度 = CELL_SIZE×4
- 樣式：底色為對應顏色，中央繪製「角色拿武器」文字/圖示（目前用 emoji + 顏色塊代替美術素材）
- 邊框：金色發光效果（strokeStyle = '#ffd700'，shadowBlur = 15）

### Ways 顯示
- 位置：原倍數欄位置（GRID_X + GRID_W/2，GRID_Y - 50）
- 格式：`1024 WAYS` → 合成後更新為 `2048 WAYS` 等
- 動畫：數字跳升時有縮放彈跳效果
